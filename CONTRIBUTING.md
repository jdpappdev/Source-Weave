# Contributing

Thanks for helping improve Source-Weave. Keep the project focused on portable, evidence-aware research practices that work across agent tools.

## Before proposing a change

- Check whether the behavior belongs in the main skill, an optional template, or a separate specialist skill.
- Prefer a small change with a clear user need over adding process for its own sake.
- Preserve the distinction between what a source says and what evidence supports.
- Do not add personal paths, private research, credentials, generated media, or machine-specific setup.
- Treat external skills and repositories as references. Do not copy their code, prompts, examples, or assets without confirming permission and attribution requirements.

## What to include

For a workflow change, explain the user problem, the expected behavior, and a concrete scenario that demonstrates the change. For an external reference, update [SOURCES.md](SOURCES.md) with its URL, version or date checked, license status, and the specific method adapted.

## Review before sharing

- Read the changed instructions as a fresh user would.
- Check that repository-relative links resolve and examples agree with the current skill.
- Inspect for secrets, private data, machine-specific paths, stale names, and claims that exceed the evidence.
- Describe review honestly: a static read-through is not a behavioral evaluation. Do not claim tests or measured improvement unless they were actually performed.
